# Gzyms

Before you change anything a user sees (Settings, a popup, a banner, a pill, CLI output), read the Interface section in CONTRIBUTING.md and follow it. Run `scripts/check.sh` before you call a change done.

Neighbouring repos: `~/Code/personal/gzyms-claude-plugin` (the public Claude Code plugin) and `~/Code/personal/gzyms-site` (gzyms.dev and the appcast). Every plugin change bumps `version` in its `.claude-plugin/plugin.json` (not verified that the marketplace needs it to update).

What goes into the next version: PRs labelled `next-release`; `scripts/next-release.sh` lists them and the version they make, `--draft` writes `whatsnew/<version>.md` from their titles.

Release: `whatsnew/<version>.md`, then `scripts/release.sh <empty out folder>`, then the steps it prints (GitHub release, `appcast.xml` into `gzyms-site/site/` and `wrangler deploy`, tap push). A published version is never replaced: a new zip under the same number breaks the cask's sha256 and the appcast signature, so a fix ships as the next version. Release, tag, appcast push and tap push only on Greg's word ("lecimy z release"). `release.sh` sends the build to Apple notarization, so even on an empty folder it waits for that word. Changes to the bundle are tested with `scripts/install-dev.sh`. The `next-release` list and `whatsnew` can be ready earlier.

Version numbers are release.feature.fix (`gzymsVersion` in `Sources/gzyms/Report.swift`). A version with at least one new feature bumps the middle number and zeroes the last (0.0.4 → 0.1.0). A version with fixes only bumps the last (0.1.0 → 0.1.1). The first number is Greg's call.

## Live test and dev install

- `scripts/install-dev.sh` replaces the running app (`~/Applications/Gzyms.app`, launchd job `dev.gzyms`) and the bar vanishes for a few seconds. Alone in the repo: run it after a green `check.sh`, in the same turn as commit and push, and say in one line "installed locally, HH:MM". When the brief says the orchestrator tests (a fan-out of agents on one app), do not install: finish `check.sh`, commit, PR, and put "not live-tested" plus 1-2 lines of what to check by hand in the PR body. With several branches waiting for a test, make one unpushed worktree `test/all` merged from them and skip the "which build" popup.
- "Done" means a new process: `pgrep -lf Gzyms.app/Contents/MacOS/gzyms` and its start time. After `install-dev` plugins start ~4 s before the scripts are swapped, so counts on pills are stale until a restart. After changing a plugin script: `gzyms plugin remove` + `add`, then `launchctl kickstart -k gui/$UID/dev.gzyms`. `gzyms debug` talks to the old binary until then.
- A copy running from `/Applications` is closed with `timeout 15 osascript -e 'tell application "/Applications/Gzyms.app" to quit'` (no SIGTERM handler), never `kill`. A build run from a scratchpad inherits the agent panel's grants, so the tuios pill is dead there; go back to the installed app after the test. A dev build does not register as a login item while `dev.gzyms.plist` exists. General view and "no second Gzyms in Login Items" can be checked on dev. Registration, the switch both ways and start after reboot only on a tap build.
- Where to look: `~/Library/Logs/Gzyms/gzyms.log` (lines `island:`, `banners:`), `gzyms debug notifications`, `gzyms debug cpu`. Read the log with Grep and `head_limit`, not `rg | tail` through rtk. Test banner: `gzyms notify --title … --body …`.
- Before a banner test check Focus/DND (`~/Library/DoNotDisturb/DB/Assertions.json`) and the pid and `etime` of Notification Center. `nc-dump` prints the NC plist as JSON. A banner that shows after ~5 s without `via ax` is Focus first, not a re-attach.
- A panel test covers open, the main action, Esc, click outside and the secondary action. A change to `SettingsNav` or `sendEvent` gets a test or "keys: not verified" in the done mail. An `NSPanel` takes its size from the content (`onGeometryChange` + `setContentSize` outside the layout pass, `fittingSize` in `open()`). A zero-size nonactivating panel is invisible to snapshots.
- A test fixture that expires (banner with a timer, toast, hover) is armed only after Greg says "ready", or made persistent. When the log or a `screencapture` already answers, say it in one sentence and ask only for the feel.
- Idle CPU: start with `gzyms debug cpu`. An animation in a window that hides (`orderOut`) is taken off the view tree, not turned off with a state flag. Every new continuous animation, timer and `TimelineView` registers in `BusyRegistry` (`Sources/GzymsCore/Busy.swift`).

## check.sh, snapshots and generated files

- `scripts/check.sh` still ends red on macOS 27.2 for 8 known snapshots: `settings-*` (5), `net-pill-proxy`, `caffeine-popup`, `star-watcher-popup` (2026-11-16). Any red test outside that list is yours. Do not record those eight until they are re-recorded on 27.2, then delete this line. `swift build` prints ~100 "unhandled" PNG warnings that hide real names: read the lines `Test <name> failed after` and `Issue recorded`, not a `grep 'failed|error:'`. `exclude: ["Snapshots"]` on the test target is not verified (check first that tests read snapshots by path). Run `swift test --filter <Suite>` while working and `check.sh` once at the end.
- `GZYMS_RECORD=1 swift test --filter GzymsUITests` rewrites every PNG, with pixel noise in `app-counts-*`, `caffeine-popup`, `music-popup`, `shelf-popup`, `wizard-missing-fda`. New pictures land in `$TMPDIR/gzyms-snapshots/`. Look at them, keep in `git status` only the screens the change was meant to touch, `git restore Tests/GzymsUITests/Snapshots/<file>` for the rest, then `scripts/check.sh`.
- After editing `skill/*.md`: `bash scripts/gen-skill.sh` (the script is not executable in git, `chmod` is not allowed). A conflict in `*.gen.swift` is never merged by hand: `git checkout --theirs <file>` and `bash scripts/gen-skill.sh`, then `rg -c '<<<<<<<|>>>>>>>' Sources Tests` must be 0. A conflict in `features.json`: sum of entries, recompute `count`. `skill/guide.md` is merged by hand. After every rebase `count` equals the number of entries.
- `PluginCatalog.swift` holds the scripts of several plugins: an `Edit` anchor contains the plugin name (`private let <plugin>`), never a bare `on_event`; check `git diff --stat` touches only that plugin.
- Before adding a helper to `GzymsCore`: `rg -n 'func <name>' Sources` (`isNewer(_:than:)` and a list-joining helper already live in `GzymsMessages.swift`).

## Project facts

- UI: strings have no `;` and no `—`. SF Symbols in the `.fill` variant, one color, no emoji; pick a new icon next to the existing ones (`rg -o 'systemName: "[^"]+"' Sources/GzymsUI`) and show it rendered before wiring it in. The bar is keyboard-first: pills and popups do not rely on hover, and a compact pill variant exists for a tight bar (notch). Exception: "Banner hints on hover" in `features.json`. A System Settings mirror page copies the real page 1:1 (card order, kind of controls): take a screenshot of that page on the current macOS first.
- A bar state with a glyph, color or text gets a parametrized `@Test(arguments:)` over all input combinations (draft × CI passed/running/failed/none × conflict), as part of the change. A new workspace source gets a fixture from the real CLI output (`omniwmctl query workspaces`) and a test "empty workspace that is active"; "active" comes from the global flag (`isCurrent`), not from "has a focused window".
- Behavior that switches on by itself from external state (Focus, screen lock, network) has a switch in Settings, safe by default, and one sentence in that section saying it follows that state. The plan in a popup lists what it will trigger in each variant (every Focus, "Work" too, cuts Slack banners). A change in the banner reading path lists the matrix style (Temporary/Persistent/none) × Desktop (on/off), marks the cells tested, and writes "not checked" for the rest.
- Reports: `AnomalyLog` and reports carry only bundle ids and counters, never notification text (`ReportScrub`). A visible behavior change (queue, preemption, levels): `rg` the term in `skill/guide.md`, `whatsnew/<next>.md` and in `~/Code/personal/gzyms-site` (`docs/index.html`, the guide copy, demo `try.js`). The site repo is fixed by the agent in the tuios session `gzyms-site` (`tuios list-sessions`, `tuios list-agents -s gzyms-site`, then `env -u TUIOS_PANE_ID tuios send-agent-message -s gzyms-site -w <pane> --subject … '…'`, sender named in the text; a `done` agent picks it up when someone enters its session).
- macOS drift is detected in `tools/probe/build.sh` and `tools/probe/check.sh` after each system update; the app has no version check beyond `testedMacOSMajor` (Greg, 2026-11-09). A new dependency on system behavior gets a scenario in `tools/probe/checks/`.
- No telemetry in the app. Popularity is counted on the server side: GitHub Releases counters saved daily and `appcast.xml` queries in Cloudflare analytics, trend on the hidden `/stats` page of gzyms-site.
- Updates: a brew cask is updated by brew, Sparkle in Settings is off by default (turning it on is allowed with a warning); an install from the site has Sparkle on. The tap is `~/Code/personal/homebrew-tap`, do not create it again. Greg rejected auto-hiding duplicate notifications (a rule of not hiding errors): the anomaly detector flags duplicates from different apps and shows the user a message.
- Before the first spike on a macOS capability (AX, notifications, windows) search for ready OSS (`gh search repos`, WebSearch) and write its mechanism (README, `ARCHITECTURE.md`) as spike 1. A spike brief lists the whole need as criteria (text, click, DM, reaction time); a result that meets a subset is "partial: missing X", never "pass".
- Greg's own queue ("what is next in gzyms?") is the newest `~/Code/personal/bazgroly/gzyms/notes/*queue*.md`: read it before `roadmap.json` and issues, answer with a list, no popup.
